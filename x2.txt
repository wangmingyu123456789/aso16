# 数字员工功能详细实现指南

> 本文档从零开始详细描述数字员工功能的完整实现过程，包括数据库设计、后端逻辑、前端交互、UI设计等所有细节。
> 适用于在相同初始代码基础上从零实现一模一样的效果。

---

## 一、功能概述

数字员工功能包含以下核心模块：

1. **数字员工管理**：以卡片形式展示所有AI助手，支持新增、编辑、删除、拖拽排序、搜索、调用统计
2. **智能对话**：与数字员工进行实时流式对话，支持历史记录、清空对话、多助手切换
3. **调用统计**：展示每个数字员工的调用次数、Token消耗等统计数据

## 二、数据库设计

### 2.1 数字员工表（assistants）

在 `app/models/db.py` 的 `upgrade_db()` 函数中创建此表：

**表结构**
- id：主键，整数，自增
- assistant_name：助手名称，文本，不能为空
- assistant_code：助手编码，文本，唯一标识（如 data_assistant）
- icon：图标类名，文本，默认值为 "fas fa-robot"（FontAwesome图标类名）
- prompt_template：Prompt模板，文本，用于系统提示词
- model_id：绑定模型ID，整数，默认0
- sort_order：排序号，整数，默认0
- is_enabled：是否启用，整数，默认1（1启用，0禁用）
- api_key：API密钥，文本，可覆盖模型配置
- api_url：API地址，文本，可覆盖模型配置
- description：描述，文本
- create_at：创建时间，文本，默认值为当前本地时间

**创建逻辑**
- 先查询 sqlite_master 表检查表是否已存在
- 不存在则执行 CREATE TABLE 语句

### 2.2 聊天历史表（chat_history）

在 `app/models/db.py` 的 `upgrade_db()` 函数中创建此表：

**表结构**
- id：主键，整数，自增
- user_id：用户ID，文本，不能为空
- assistant_id：助手ID，整数，默认0
- model_id：模型ID，整数，默认0
- role：角色，文本，不能为空（user表示用户消息，assistant表示助手回复）
- content：消息内容，文本，不能为空
- prompt_tokens：输入token数，整数，默认0
- completion_tokens：输出token数，整数，默认0
- total_tokens：总token数，整数，默认0
- create_at：创建时间，文本，默认值为当前本地时间

**创建逻辑**
- 先查询 sqlite_master 表检查表是否已存在
- 不存在则执行 CREATE TABLE 语句

### 2.3 菜单初始化

在 `app/models/db.py` 的 `_init_default_data()` 函数中，在"核心业务"一级菜单下添加"数字员工"子菜单：

**菜单项配置**
- code：biz_employees
- name：数字员工
- icon：layui-icon-user
- url：/admin/agent
- parent_code：biz（核心业务）
- sort_order：2

**权限分配**
- 创建菜单后，查询admin角色的ID
- 在 role_functions 表中插入记录，将菜单权限分配给admin角色

**升级函数中的菜单检查**
- 在 `upgrade_db()` 函数中，检查 biz_employees 菜单是否存在
- 不存在则创建并分配admin权限

## 三、数据访问层（Model层）

### 3.1 创建文件 app/models/assistant.py

此文件包含两个Repository类：AssistantRepository 和 ChatHistoryRepository

### 3.2 AssistantRepository 类

**get_assistant_list 方法**
- 参数：page（页码，默认1）、limit（每页条数，默认20）、keyword（搜索关键词，默认空）
- 计算偏移量：offset = (page - 1) * limit
- 构建SQL：从assistants表左连接models表，获取助手信息和绑定的模型名称/编码
- 如果有keyword，添加WHERE条件：助手名称或编码包含关键词（LIKE模糊匹配）
- 排序：先按sort_order升序，再按id升序
- 分页：LIMIT和OFFSET
- 返回：字典列表

**get_assistant_count 方法**
- 参数：keyword（搜索关键词）
- 构建SQL：COUNT(*) 统计assistants表记录数
- 如果有keyword，添加WHERE条件
- 返回：整数

**get_assistant_by_id 方法**
- 参数：assistant_id
- 构建SQL：从assistants表左连接models表，WHERE id = ?
- 返回：字典（如果存在）或 None

**get_enabled_assistants 方法**
- 构建SQL：获取所有 is_enabled = 1 的助手，左连接models表
- 排序：sort_order升序，id升序
- 返回：字典列表

**add_assistant 方法**
- 参数：assistant_name、assistant_code、icon、prompt_template、model_id、sort_order、is_enabled、api_key、api_url、description
- 执行INSERT语句插入assistants表
- 使用try-except捕获异常（如编码重复）
- 成功返回True，失败返回False

**update_assistant 方法**
- 参数：assistant_id 加上 add_assistant 的所有参数
- 执行UPDATE语句更新assistants表
- 使用try-except捕获异常
- 成功返回True，失败返回False

**delete_assistant 方法**
- 参数：assistant_id
- 执行DELETE语句删除单条记录
- 使用try-except捕获异常
- 成功返回True，失败返回False

**batch_delete_assistant 方法**
- 参数：assistant_ids（ID列表）
- 构建IN子句：根据ID数量动态生成占位符（如 ?,?,?）
- 执行DELETE语句批量删除
- 使用try-except捕获异常
- 成功返回True，失败返回False

**update_sort_order 方法**
- 参数：assistant_ids（ID列表，按新顺序排列）
- 遍历ID列表，为每个ID更新sort_order为索引+1
- 使用事务确保一致性
- 成功返回True，失败返回False

**get_usage_stats 方法**
- 参数：assistant_id（可选）、days（统计天数，默认7）
- 构建SQL：从assistants表左连接chat_history表
- 按助手分组，统计：调用次数（COUNT）、总token（SUM）、输入token（SUM）、输出token（SUM）
- 如果days > 0，添加时间过滤：create_at >= 当前时间减去days天
- 排序：sort_order升序
- 返回：字典列表

### 3.3 ChatHistoryRepository 类

**save_message 方法**
- 参数：user_id、assistant_id、model_id、role、content、prompt_tokens、completion_tokens、total_tokens
- 执行INSERT语句插入chat_history表
- 使用try-except捕获异常
- 成功返回True，失败返回False

**get_history 方法**
- 参数：user_id、assistant_id（可选）、limit（限制条数，默认50）
- 构建SQL：从chat_history表查询，WHERE user_id = ?
- 如果指定assistant_id，添加 AND assistant_id = ?
- 排序：create_at升序（时间正序）
- 分页：LIMIT
- 返回：字典列表

**clear_history 方法**
- 参数：user_id、assistant_id（可选）
- 如果指定assistant_id，删除该用户该助手的所有历史记录
- 否则删除该用户的所有历史记录
- 使用try-except捕获异常
- 成功返回True，失败返回False

## 四、模型层修改

### 4.1 修改文件 app/models/model.py

在 ModelRepository 类中添加 **stream_model_chat** 静态方法：

**方法功能**
- 实现与大语言模型的流式对话
- 使用生成器（yield）逐块返回响应内容

**实现逻辑**
1. 构建请求头：
   - Authorization：Bearer {api_key}
   - Content-Type：application/json

2. 构建请求体（JSON）：
   - model：模型编码
   - messages：消息列表
   - stream：true（开启流式响应）

3. 使用 httpx.Client 发起请求：
   - 超时时间：60秒
   - 使用 `client.stream("POST", ...)` 上下文管理器（注意：不是 client.post 的 stream 参数）

4. 逐行读取响应：
   - 跳过空行
   - 解析以 "data: " 开头的行
   - 如果 data 内容是 "[DONE]"，返回 {"done":true} 并结束
   - 否则解析JSON，提取 delta.content
   - 如果有content，返回 {"content": 内容}
   - 如果有usage信息，返回 {"usage": usage数据}

5. 异常处理：
   - 如果状态码不是200，返回 {"error": "API Error: 状态码"}
   - 如果发生异常，返回 {"error": 异常信息}

### 5.4 AdminAssistantApiHandler 类

**功能**：助手管理API接口（增删改查、排序、统计）

**GET方法**
- 需要认证
- 设置响应头：Content-Type 为 application/json
- 根据action参数处理不同请求：

1. **action = "stats"**（获取调用统计）
   - 获取days参数（默认7天）
   - 调用 AssistantRepository.get_usage_stats(days=days)
   - 返回JSON：{code: 0, msg: "success", data: 统计数据}

2. **action = "enabled"**（获取启用的助手）
   - 调用 AssistantRepository.get_enabled_assistants()
   - 返回JSON：{code: 0, msg: "success", data: 助手列表}

3. **action = "detail"**（获取助手详情）
   - 获取id参数
   - 调用 AssistantRepository.get_assistant_by_id(id)
   - 如果存在，返回JSON：{code: 0, msg: "success", data: 助手详情}
   - 否则返回：{code: 1, msg: "助手不存在"}

4. **默认**（分页获取助手列表）
   - 获取keyword、page、limit参数
   - 调用 AssistantRepository.get_assistant_list(page, limit, keyword)
   - 调用 AssistantRepository.get_assistant_count(keyword)
   - 返回JSON：{code: 0, msg: "success", data: 列表, count: 总数}

**POST方法**
- 需要认证
- 设置响应头：Content-Type 为 application/json
- 根据action参数处理不同请求：

1. **action = "sort"**（更新排序）
   - 解析请求体JSON，获取ids数组
   - 调用 AssistantRepository.update_sort_order(ids)
   - 返回JSON：{code: 0/1, msg: 结果消息}
   - 异常处理：捕获异常并返回错误信息

2. **默认**（新增或编辑助手）
   - 获取表单参数：assistant_name、assistant_code、icon、prompt_template、model_id、sort_order、is_enabled、api_key、api_url、description
   - 验证：名称和编码不能为空
   - 判断是新增还是编辑：检查是否有id参数
     - 有id：调用 update_assistant，返回"修改成功/失败"
     - 无id：调用 add_assistant，返回"新增成功/失败"

**DELETE方法**
- 需要认证
- 设置响应头：Content-Type 为 application/json
- 解析请求体JSON，获取ids数组
- 验证：ids不能为空
- 调用 AssistantRepository.batch_delete_assistant(ids)
- 返回JSON：{code: 0/1, msg: 结果消息}
- 异常处理：捕获异常并返回错误信息

### 5.8 ChatSendHandler 类

**功能**：处理流式聊天请求（核心对话接口）

**POST方法**
- 需要认证
- 获取参数：assistant_id、content
- 验证：
  - assistant_id不能为0
  - content不能为空
  - 助手必须存在且已启用
  - 助手必须绑定了模型
  - 模型必须存在且状态为启用

- 保存用户消息：
  - 调用 ChatHistoryRepository.save_message，role为"user"

- 构建消息列表：
  1. 如果助手有prompt_template，添加system消息
  2. 获取历史聊天记录（最近20条），逐条添加到messages
  3. 添加当前用户消息

- 设置SSE响应头：
  - Content-Type：text/event-stream
  - Cache-Control：no-cache
  - X-Accel-Buffering：no
  - 调用 flush() 确保响应头已发送

- 创建队列（queue.Queue）用于线程间通信
- 创建 full_content 列表用于收集完整回复
- 创建 has_error 标记是否有错误

- 启动后台线程（stream_worker）：
  1. 获取API配置（优先使用助手的api_key/api_url，否则使用模型的）
  2. 调用 ModelRepository.stream_model_chat 获取流式响应
  3. 逐块放入队列
  4. 如果发生异常，将错误信息放入队列
  5. 完成后放入None标记结束

- 主线程循环读取队列：
  1. 超时时间60秒
  2. 如果收到None，结束循环
  3. 将数据以SSE格式写入响应（data: {JSON}\n\n）
  4. 调用 flush() 立即发送
  5. 解析JSON，收集content内容
  6. 如果有error，标记错误并结束
  7. 如果队列超时，返回"请求超时"错误

- 调用 finish() 结束HTTP响应

- 如果有完整回复且没有错误：
  - 调用 ChatHistoryRepository.save_message 保存助手回复，role为"assistant"

## 六、前端模板设计

### 6.1 数字员工管理页面（admin/assistant.html）

**页面结构**
- 继承 layout.html
- 包含两个block：body 和 extra_script

**CSS样式设计**

   - 右侧按钮：调用统计按钮（粉紫渐变色）、新增按钮（绿色渐变色）

2. **卡片网格布局**
   - 使用CSS Grid：3列等宽，间距20px
   - 响应式：固定3列布局

3. **卡片设计**
   - 白色背景，灰色边框，圆角8px，内边距20px

   - 可拖拽：cursor为grab

4. **卡片头部**
   - 图标：48x48圆角方块，渐变色背景（紫色），白色图标，20px大小
   - 标题：16px，加粗，深灰色
   - 编码：12px，浅灰色

5. **卡片主体**
   - Prompt预览：13px，灰色，最多显示3行，超出省略
   - 使用 -webkit-line-clamp: 3 实现多行省略

6. **卡片底部**
   - 左侧：模型信息（蓝色图标 + 模型名称）
   - 右侧：操作按钮组（对话、编辑、删除）
   - 按钮样式：小号按钮，不同颜色区分功能

7. **状态徽章**
   - 绝对定位在右上角
   - 已启用：绿色背景 + 绿色文字
   - 已禁用：红色背景 + 红色文字

8. **拖拽手柄**
   - 绝对定位在左上角
   - 灰色，可拖拽图标

9. **排序号**
   - 绝对定位在右下角
   - 11px，浅灰色

10. **空状态**
    - 居中显示，灰色文字
    - 大图标 + 提示文字

**JavaScript逻辑**

1. **CSRF Token获取函数**
   - 从cookie中读取_xsrf token
   - 用于POST请求的安全验证

2. **页面初始化**
   - 使用Layui的layer、jquery、form模块
   - 定义全局变量：currentPage、totalCount、models数组

3. **加载模型列表**
   - AJAX请求 /admin/models/api
   - 获取所有模型（page_size=100）
   - 存储到models数组，用于表单中的下拉选择

4. **加载助手列表**
   - AJAX请求 /admin/api/assistant
   - 传递page、limit、keyword参数
   - 渲染卡片网格

5. **渲染卡片函数**
   - 遍历数据，生成HTML
   - 每个卡片包含：拖拽手柄、状态徽章、图标、名称、编码、Prompt预览、模型信息、操作按钮、排序号
   - 调用 initDragSort() 初始化拖拽排序

6. **拖拽排序实现**
   - 使用HTML5 Drag and Drop API
   - dragstart：记录被拖拽的卡片，添加dragging类
   - dragover：计算鼠标位置，判断插入位置（上半部分插入前面，下半部分插入后面）
   - dragend：移除dragging类，获取新顺序的ID数组，AJAX提交排序更新
   - 排序成功后显示提示消息

7. **新增/编辑表单**
   - 使用layer.open打开弹窗
   - 表单字段：助手名称、助手编码、图标、Prompt模板、绑定模型下拉、API Key、API URL、描述、启用状态（单选按钮）

   - 新增时：表单为空
   - 提交时：AJAX POST到 /admin/api/assistant
   - 成功后关闭弹窗，重新加载列表

8. **搜索功能**
   - 点击搜索按钮：重置页码为1，重新加载数据
   - 点击重置按钮：清空搜索框，重新加载数据

9. **对话按钮**
   - 跳转到 /admin/agent/chat?assistant_id={id}

10. **删除功能**
    - layer.confirm确认对话框
    - AJAX DELETE到 /admin/api/assistant
    - 传递ids数组
    - 成功后重新加载列表

11. **调用统计按钮**
    - 跳转到 /admin/agent/usage

## 七、路由注册

在 `app.py` 的 make_app() 函数中添加以下路由：

- /admin/agent -> AdminAssistantConfigHandler（助手配置页面）

## 十、已知问题与修复记录

### 10.1 路由不匹配问题

**问题描述**
- 前端AJAX调用 `/admin/api/assistant`
- 但路由注册为 `/admin/agent/api`
- 导致数字员工列表无法加载

**修复方法**
- 将路由改为 `(r"/admin/api/assistant", AdminAssistantApiHandler)`
- 确保前端调用URL与路由注册完全一致

### 10.2 httpx stream参数错误

**问题描述**
- httpx v0.28.1 不支持 `client.post(..., stream=True)` 参数
- 报错："Client.post() got an unexpected keyword argument 'stream'"

**修复方法**
- 改用 `with client.stream("POST", api_url, headers=headers, json=payload) as response:` 上下文管理器
- 在上下文管理器内使用 `response.iter_lines()` 逐行读取响应

### 10.3 current_page未定义

**问题描述**
- 模板中引用了 current_page 变量用于菜单高亮
- 但Handler渲染时未传入该变量

**修复方法**
- 在 render() 方法中添加 `current_page="agent"` 参数
- 确保所有相关页面都传入正确的current_page值

### 10.4 内置数字员工未显示

**问题描述**
- 刷新页面后没有显示内置的五个数字员工

**修复方法**
- 检查数据库assistants表是否有初始数据
- 在 `_init_default_data()` 函数中添加默认助手数据插入逻辑
- 或在页面加载时检查，如果为空则自动创建

## 十四、数据流转说明

### 14.1 新增助手流程

1. 用户点击"新增助手"按钮
2. 前端弹出表单弹窗
3. 用户填写表单并提交
4. 前端AJAX POST到 /admin/api/assistant
5. 后端验证数据，调用 AssistantRepository.add_assistant
6. 数据库插入记录
7. 返回成功JSON
8. 前端关闭弹窗，重新加载列表

### 14.2 对话流程

1. 用户点击"对话"按钮
2. 跳转到 /admin/agent/chat?assistant_id={id}
3. 页面加载，获取启用的助手列表
4. 选中指定助手，加载聊天历史
5. 用户输入消息，点击发送
6. 前端AJAX POST到 /api/chat/send
7. 后端验证助手和模型状态
8. 保存用户消息到chat_history
9. 构建消息列表（system + history + current）
10. 启动后台线程调用模型API
11. 流式响应逐块返回前端
12. 前端逐块更新助手回复内容
13. 完成后保存助手回复到chat_history

### 14.3 拖拽排序流程

1. 用户拖拽卡片到新位置
2. 前端计算新顺序的ID数组
3. AJAX POST到 /admin/api/assistant?action=sort
4. 后端调用 AssistantRepository.update_sort_order
5. 遍历ID数组，更新每个助手的sort_order
6. 返回成功JSON
7. 前端显示提示消息

### 14.4 调用统计流程

1. 用户点击"调用统计"按钮
2. 跳转到 /admin/agent/usage
3. 后端获取days参数（默认7天）
4. 调用 AssistantRepository.get_usage_stats
5. SQL左连接assistants和chat_history表
6. 按助手分组统计调用次数和token消耗
7. 渲染模板，显示统计卡片

## 十五、安全注意事项

1. **CSRF保护**
   - 所有POST/DELETE请求必须包含_xsrf token
   - 前端从cookie读取token并添加到请求中

2. **认证保护**
   - 所有管理页面需要登录认证（@tornado.web.authenticated）
   - 聊天页面也需要认证

3. **SQL注入防护**
   - 使用参数化查询（?占位符）
   - 不直接拼接SQL字符串

4. **XSS防护**
   - 前端使用escapeHtml函数转义用户输入
   - 替换&、<、>、"为HTML实体

5. **异常处理**
   - 数据库操作使用try-except捕获异常
   - 失败时回滚事务
   - 返回友好的错误信息
