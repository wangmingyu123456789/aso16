# CToS 前端详细设计

> **文档版本**: 1.0.0  
> **最后更新**: 2026-05-27  
> **项目定位**: 后端API测试客户端 — 覆盖11个模块、113+个后端接口的简易前端实现  
> **技术栈**: 原生 HTML5 + CSS3 + JavaScript (Vanilla JS)，无需构建工具

---

## 一、设计目标

### 1.1 核心目标

1. **模拟客户端**：作为后端REST API的简易客户端，覆盖后端的**全部11个模块**
2. **功能验证**：通过可视化界面便捷地调用后端所有API，用于开发和测试
3. **清晰分层**：HTML结构、CSS样式、JS逻辑三层分离，易于维护和扩展
4. **无需部署**：纯静态页面，直接通过浏览器打开即可使用（需后端运行）

### 1.2 覆盖的模块

| 模块 | 前端页面 | 支持的接口数 | 备注 |
|------|---------|------------|------|
| Auth 认证 | 登录页 + 认证模块 | 4 | 登录/注册/获取用户/健康检查 |
| Chat 智能问数 | 智能问数模块 | 3 | 对话列表/创建/发送消息(SSE) |
| Watch 智能瞭望 | 智能瞭望模块 | 4 | 列表/创建/触发/历史 |
| Workers 数字员工 | 数字员工模块 | 4 | 工作列表/员工列表/详情/执行 |
| Dispatch 派遣 | 派遣执行模块 | 4 | 派遣/记录列表/详情/工具列表 |
| Cleaning 数据清洗 | 数据清洗模块 | 4 | 日志/启动/统计/工具 |
| Warehouse 知识仓库 | 知识仓库模块 | 4 | 文章/分类/统计/域名 |

```

                                │
```

```
                                │
                                ▼
                        fetch() 发送 HTTP 请求
                                │
                                ▼
                     ┌──────────────────┐

                     │ ├─ JSON → 显示结果 │
                     │ └─ SSE → 流式追加  │
```

### 3.3 关键设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 构建工具 | 无 (Vanilla JS) | 无需构建步骤，直接双击 index.html 即可使用 |
| HTTP客户端 | 原生 fetch() | 内置Promise支持，无需额外库 |
| Token存储 | localStorage | 持久化登录状态，刷新页面后自动恢复 |
| UI框架 | 无 | 避免依赖，轻量简洁 |
| SSE处理 | ReadableStream | 浏览器原生支持流式读取，逐 token 展示 |

## 五、API客户端设计 (`api.js`)

### 5.1 核心方法 `API.call()`

```javascript
API.call(module, path, method, body, customHandler)
```

**参数说明**:

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| module | string | ✅ | 模块名（auth/chat/watch/workers/dispatch/cleaning/warehouse/sentiment/dashboard/admin/im） |
| path | string | ✅ | API路径，如 `/api/auth/me` |
| method | string | ✅ | HTTP方法（GET/POST/PUT/DELETE） |
| body | object | ❌ | 请求体JSON对象 |
| customHandler | function | ❌ | 自定义响应处理函数 |

**处理流程**:

1. 根据 module + path 拼装输出DOM的ID
2. 显示加载遮罩
3. 注入 `Authorization: Bearer <token>` 头
4. 发送 fetch 请求
5. 检测 Content-Type：
   - `text/event-stream` → 调用 `handleSSE()` 流式处理
   - 其他 → JSON 解析 → 调用 `showResult()` 显示
6. 隐藏加载遮罩

### 5.2 SSE流式处理

```javascript
API.handleSSE(response, outputEl)
```

- 使用 `ReadableStream` 逐块读取响应体
- 按 `\n` 分割行数据
- 识别 `data:` 前缀提取数据
- 使用 `span.token` 元素逐 token 追加显示（带 fadeIn 动画）
- 支持 OpenAI API 格式的 delta 字段解析

### 5.3 Token管理

- `API.token` — 内存中保存 JWT Token
- `API.currentUser` — 当前用户信息
- `API.login()` — 登录成功后保存 token 和 user 到内存
- `localStorage.getItem('ctos_token')` — 页面加载时恢复 token
- 所有 API 调用自动注入 `Authorization` 头

### 6.2 时间处理设计

#### 6.2.1 设计原则

前端所有时间渲染遵循 **后端存 UTC+0，前端做本地时区偏移** 的原则：

1. **后端独立决定时间**：所有 `created_at` / `updated_at` / `collected_at` 等字段由数据库 `server_default=text("CURRENT_TIMESTAMP")` 在写入行时自动生成，**前端不传任何时间参数**
2. **数据库写入 UTC+0**：SQLite 的 `CURRENT_TIMESTAMP` 始终返回 UTC 时间（与系统时区无关）
3. **后端返回 naive ISO**：通过 `.isoformat()` 返回不带 Z 后缀的 ISO 字符串（如 `"2026-05-28T05:29:42"`）
4. **前端正确偏移**：JS 解析时主动标记为 UTC+0，再转换到用户本地时区显示

#### 6.2.2 核心工具函数 `_formatTime()`

```javascript
_formatTime(isoStr, format = 'full') {
    if (!isoStr) return '';
    // 给后端返回的无时区字符串添加 Z 后缀 → 正确识别为 UTC
    const d = new Date(isoStr.endsWith('Z') ? isoStr : isoStr + 'Z');
    if (isNaN(d.getTime())) return isoStr;
    if (format === 'date') return d.toLocaleDateString('zh-CN');
    if (format === 'time') return d.toLocaleString('zh-CN', { hour: '2-digit', minute: '2-digit' });
    if (format === 'short') return d.toLocaleString('zh-CN', { month: 'short', day: 'numeric', hour: '2-digit', minute: '2-digit' });
    return d.toLocaleString('zh-CN');
}
```

**format 参数说明：**

| 格式值 | 输出示例（UTC+9 东京时区用户） | 适用场景 |
|--------|-------------------------------|---------|
| `'full'` | `"2026/5/28 14:29:42"` | 详细时间展示 |
| `'date'` | `"2026/5/28"` | IM 消息日期分隔线 |
| `'time'` | `"14:29"` | IM 单条消息时间戳 |
| `'short'` | `"5月28日 14:29"` | 会话列表、对话列表时间 |

#### 6.2.3 覆盖的时间渲染位置

| 模块 | 渲染函数 | 时间字段 | 格式 |
|------|---------|---------|------|
| 数据清洗-待清洗 | `loadUncleanedData()` | `collected_at` | `full` |
| 数据清洗-已清洗 | `loadCleanedArticles()` | `created_at` | `full` |
| 舆情分析列表 | `loadSentimentAnalyses()` | `created_at` | `full` |
| 大屏快照弹窗 | `openDashboardModal()` | `snapshot_at` | `full` |
| 智能问数-对话列表 | `loadChatConversations()` | `updated_at` | `short` |
| 智能问数-消息渲染 | `renderMessage()` | `created_at` | `full` |
| IM 会话列表 | `loadIMConversations()` | `last_msg.created_at` | `short` |
| IM 消息日期分隔 | `loadIMMessagesByChat()` | `created_at` | `date` |
| IM 单条消息 | `_renderIMMessage()` | `created_at` | `time` |

#### 6.2.4 消息发送时间处理

IM 消息发送采用 **先渲染临时消息，后原地更新** 策略：

1. 临时消息使用 `new Date().toISOString()` 作为占位时间（无时区标记）
2. 后端返回确认后，用 `_parseIMTime(res.created_at)` 更新 `<span class="im-msg-time">` 的文本
3. 最终显示的永远是后端返回的 UTC 时间经偏移后的正确本地时间

```javascript
// 步骤1：临时消息占位
const tempMsg = {
    created_at: new Date().toISOString()  // 仅作占位
};
this._renderIMMessage(tempMsg, chat.type);

// 步骤2：后端确认后原地更新
if (timeEl && res.created_at) {
    timeEl.textContent = this._parseIMTime(res.created_at);
}
```

### 6.4 IM 模块关键设计

IM（智能聊天）模块在后来的迭代中进行了大量增强，以下是关键设计要点：

#### 6.4.1 消息发送无闪烁 (`sendIMMessage`)

发送消息流程经过优化，无闪烁：

1. 先渲染临时消息（即时显示，`new Date().toISOString()` 作为占位时间）
2. API 发送完成后，**原地更新**最后一条 `.im-msg.sent` 元素的时间文本为服务器返回的正确时间（通过 `_parseIMTime()` 做 UTC→本地偏移）
3. 手动更新 `this._im.messages` 内存数组
4. 刷新会话列表（不影响消息区域）

不再调用 `loadIMMessagesByChat()` 清空重绘，避免闪烁。

#### 6.4.2 私聊消息轮询 (`_pollIMMessages`)

通过 8 秒定时器轮询新消息，仅当消息数量增加时才追加渲染新消息，不重置已有消息列表。

#### 6.4.3 会话列表去重

后端 `GET /api/im/conversations` 对私聊会话进行 key 归一化（`user_{小ID}_{大ID}`），同一对用户只返回一条会话记录。前端直接渲染返回数据，无需额外去重逻辑。

## 十、开发启动

### 10.1 前提条件

1. 后端服务运行在 `http://localhost:8000`（FastAPI）
2. 现代浏览器（支持 fetch、ReadableStream、ES6+）

### 10.2 启动方式

```bash
# 方式1：直接打开 HTML 文件
打开 CToS2Front/frontend/index.html

# 方式2：通过 VS Code Live Server（推荐）
# 右键 index.html → Open with Live Server

# 方式3：使用 Python 简易 HTTP 服务器
cd CToS2Front/frontend
python -m http.server 8080
# 访问 http://localhost:8080
```

### 10.3 使用流程

1. 确保后端已启动（`python CToS2Back/app.py`）
2. 打开前端页面
3. 点击「检查服务健康状态」确认后端可达
4. 注册新账号或使用已有账号登录
5. 按侧边栏导航测试各模块 API

## 十一、已知限制

| 限制 | 说明 |
