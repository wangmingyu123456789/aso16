需要实现用户侧+管理侧的所有功能及业务，重点考察需求完整、功能完整、系统风格去AI化、软件能力

## 3. 功能模块

### 3.1 首页 (Index)

- 展示系统概览页面
- 根据用户角色显示不同的导航入口

### 3.2 智能问数 (Chat) — AI 对话系统

#### 3.2.1 功能描述

提供基于大语言模型的智能对话能力，支持多会话管理、流式问答响应。

#### 3.2.2 功能需求

1. **会话管理**：
   - 创建新会话（自动命名）
   - 会话列表展示（按更新时间倒序）
   - 删除指定会话
   - 首次消息自动更新会话标题（取前 25 字）

2. **流式问答**：
   - 基于 SSE (Server-Sent Events) 的实时流式输出
   - 逐 token 推送给前端
   - 支持中断响应

3. **LLM 集成**：
   - 兼容 OpenAI API 格式
   - 支持自定义 API Base URL、API Key、模型名称
   - 自动从 api_keys 表读取配置
   - 未配置时使用 Mock 模式（提示用户配置）

4. **对话历史**：
   - 保存完整对话记录
   - 每次请求携带最近 20 条消息作为上下文
   - Token 用量估算与记录

5. **异常处理**：
   - API 请求超时处理
   - 连接错误处理
   - 错误信息 SSE 推送

### 3.3 智能瞭望 (Watch) — 网络数据采集系统

#### 3.3.1 功能描述

配置定时网络数据采集任务，支持自定义 HTTP 请求参数，自动采集并存储响应数据。

#### 3.3.2 功能需求

1. **瞭望源管理**：
   - CRUD：创建、查看、编辑、删除采集源
   - 配置参数：名称、URL、请求方法（GET/POST）、Headers（JSON）、Body 模板、采集间隔（秒）、启用/禁用

2. **采集执行**：
   - 手动触发单源采集
   - 后台自动定时扫描（每 60 秒检测到期源）
   - 异步 HTTP 请求（httpx）执行采集
   - 支持 GET/POST 及其他 HTTP 方法
   - 自动设置 User-Agent

3. **数据存储**：
   - 原始响应数据（限制 10000 字符）
   - 尝试解析 JSON 结构化数据
   - 记录采集状态（success/error）
   - 记录采集时间

4. **历史查看**：
   - 按瞭望源查看采集历史
   - 支持分页/条数限制

5. **数据导出**：
   - 导出指定瞭望源的采集数据为 JSON 文件

6. **教学场景**（代码注释明确说明）：
   - 可演示 CSRF 攻击场景（通过自定义请求体/头触发目标操作）
   - 可演示 SSRF 攻击场景（通过 URL 探测内网服务）
   - 生产环境需添加白名单限制

### 3.4 数字大屏 (Dashboard) — 数据可视化

#### 3.4.1 功能描述

全屏实时数据可视化大屏，展示系统运行关键指标。

#### 3.4.2 功能需求

1. **实时指标展示**：
   - 瞭望源总数
   - 今日采集数据量
   - 总采集数据量
   - Token 总消耗
   - 注册用户数
   - 系统运行时长（uptime）

2. **时间序列数据**：
   - 过去 24 小时逐时采集趋势图
   - 过去 7 天逐日 Token 消耗趋势图

3. **数据刷新**：
   - 支持前端定期轮询获取最新统计数据

### 3.5 数字员工 (Digital Workers) — AI 智能代理引擎

#### 3.5.1 功能描述

基于 LLM 的智能代理系统，通过"工作定义"和"数字员工"两层抽象，实现可扩展的 AI 任务执行引擎。

#### 3.5.2 架构设计

```
工作定义 (Job)          →   数字员工 (Worker)       →   执行引擎 (Engine)
┌─────────────────┐       ┌─────────────────┐       ┌─────────────────┐
│ 工作名称/描述    │       │ 员工名称/图标    │       │ LLM 调用         │
│ 工作唯一编码     │       │ 绑定工作(job_code)│       │ 工具注册表      │
│ 关联工具列表     │       │ 绑定的 API Key   │       │ 工具派发执行    │
│ 提示词模板       │       │ 启用/禁用        │       │ 结果回传 LLM    │
└─────────────────┘       └─────────────────┘       └─────────────────┘
```

#### 3.5.3 三个预定义工作

| 工作 | 编码 | 工具 | 数据源 |
|------|------|------|--------|
| 🌤️ 天气查询 | weather_query | get_weather | wttr.in 免费天气 API |
| 🎬 影视搜索 | movie_search | search_movie | 内置电影数据库 |
| 🧹 数据清洗 | data_cleaning | 5 个数据清洗工具 | 瞭望采集数据 |

#### 3.5.4 功能需求

1. **工作管理 (Job CRUD)**：
   - 创建/编辑/删除工作定义
   - 配置工作名称、编码、描述、图标、排序
   - 关联工具列表
   - 配置中文提示词模板（含 `{tools}` 占位符自动渲染）

2. **员工管理 (Worker CRUD)**：
   - 创建/编辑/删除数字员工
   - 绑定工作 (job_code)
   - 绑定 API Key（可自动选择全局第一个）
   - 配置系统提示词
   - 启用/禁用切换
   - 排序调整

3. **工具注册机制**：
   - 基于 `@register_tool` 装饰器的工具注册
   - 自动提取函数签名和文档字符串作为工具描述
   - 支持异步工具函数

4. **执行引擎**：
   - 接收用户消息 → 渲染系统提示词（含工具列表）
   - 调用 LLM → 解析 JSON 工具调用指令
   - 派发执行工具 → 工具结果回传给 LLM
   - LLM 生成最终自然语言回复
   - 保存执行记录

5. **执行记录**：
   - 记录用户查询、调用的工具、参数、工具结果、最终回复
   - 执行状态标记（success/error）

6. **双端界面**：
   - **数字工作台（用户端）**：按工作卡片展示，用户直接使用
   - **派遣工作台（管理端）**：表格化管理所有员工和工作

7. **API 接口**：
   - 按员工 ID 派遣：`POST /api/dispatch`
   - 按工作编码派遣：`POST /api/dispatch/by-job`
   - 员工 CRUD：`/api/workers/*`
   - 工作 CRUD：`/api/jobs/*`
   - 工具列表：`GET /api/tools`

### 3.6 数据清洗 (Data Worker) — AI 辅助数据清洗

#### 3.6.1 功能描述

将智能瞭望采集的原始数据进行 AI 清洗，提取结构化信息，存入数据仓库。

#### 3.6.2 工作流程

```
瞭望采集数据 → AI/规则提取结构化信息 → 存入数据仓库 → 标记已清洗
```

#### 3.6.3 功能需求

1. **AI 清洗**：
   - 调用大模型 (OpenAI 兼容 API) 提取结构化信息
   - 提取字段：标题 (title)、主体名称 (domain_name)、纯文本正文 (content)
   - 要求 LLM 返回纯 JSON
   - 温度参数 0.3（低随机性）

2. **规则提取降级**：
   - 当 AI 不可用时，使用正则表达式提取
   - 提取 `<title>` 标签
   - 提取 `<body>` 或 `<article>` 内容
   - 去除 HTML 标签

3. **清洗操作**：
   - 单条清洗：指定 watch_data_id
   - 批量清洗：清洗所有未处理数据
   - 清洗结果保存到 warehouse_articles 表

4. **待处理数据管理**：
   - 按瞭望源筛选
   - 按状态筛选（全部/待清洗/已清洗/失败）
   - 关键词搜索
   - 数据详情预览

### 3.7 数据仓库 (Warehouse) — 结构化数据管理

#### 3.7.1 功能描述

存储和管理经 AI 清洗后的结构化文章数据，提供检索、编辑和统计功能。

#### 3.7.2 功能需求

1. **文章管理**：
   - 列表展示：支持分页、按域名筛选、按状态筛选（草稿/已发布）
   - 关键词搜索（标题/内容）
   - 查看文章详情
   - 编辑文章：标题、主体名称、内容、状态
   - 删除文章

2. **域名管理**：
   - 从 URL 自动提取域名（去 www. 前缀）
   - 同一域名下 domain_name 保持唯一

3. **统计信息**：
   - 总文章数
   - 草稿/已发布文章数
   - 今日新增文章数
   - 待清洗/已清洗/失败数据数

### 3.8 API Key 管理

#### 3.8.1 功能描述

管理多个大模型 API 密钥配置，支持不同模型提供方。

#### 3.8.2 功能需求

1. **CRUD 操作**：
   - 创建 API Key 配置：名称、提供方、Base URL、API Key、模型名称
   - 高级参数：Max Tokens、Temperature、Top P
   - 启用/禁用
   - 用途标注（chat/dataworker/all）
   - 排序

2. **测试连接**：
   - 发送测试请求验证 API Key 可用性
   - 返回模型名称、Token 消耗、响应预览

3. **自动选择**：
   - 按 sort_order 排序取第一个启用的 Key
   - 支持按用途筛选

### 3.9 管理后台 (Admin)

#### 3.9.1 功能描述

系统管理中心，提供用户管理、权限管理、系统配置和 Token 统计。

#### 3.9.2 功能需求

1. **用户管理**：
   - 用户列表（含角色、权限、状态）
   - 创建用户（可分配角色和权限）
   - 启用/禁用用户
   - 修改用户角色
   - 修改用户权限（user_management / permission_management）
   - 删除用户（不可删除 root）

2. **系统配置**：
   - 模型基础地址
   - 模型 API Key
   - 模型名称
   - Token 限制

3. **Token 统计**：
   - 按天统计 Token 消耗（近 7 天）
   - 按用户统计 Token 消耗（排行榜）
