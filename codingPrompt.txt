继续前端-即使通信功能大模块的开发
基于现有系统（已有用户侧、管理侧框架），新增智能聊天子系统，实现类似微信的即时通信功能，包含私聊、群聊、通讯录、数字员工等，并要求后台管理相关功能。
我将分成五个阶段完成：
第一阶段：基础框架与用户体系
任务一
一）、功能定义
1.1 用户入口
菜单位置：在现有系统侧边栏菜单中，增加一个一级菜单项“智能聊天”，图标采用消息气泡或对话风格。
访问权限：所有已登录用户（无论角色）均可访问，无需额外授权。
默认界面：点击后进入聊天主界面，若用户从未使用过聊天功能，则显示空状态提示（如“暂无会话，去添加好友开始聊天”）。
1.2 主界面功能区域（左右结构）
左侧面板（会话/联系人列表）：
顶部标签页：支持切换“会话”和“通讯录”。
会话列表：展示最近聊天的私聊和群聊记录，按最后消息时间倒序排列。每条会话显示头像、名称、最后一条消息预览、未读消息数（小红点或数字）。
通讯录列表：展示好友列表和群聊列表，支持分组（如“我的好友”、“我的群聊”），可点击进入详情或发起聊天。
搜索框：全局搜索好友昵称、群名称，支持模糊匹配。
右侧面板（聊天窗口）：
顶部：显示当前聊天对象（好友昵称或群名称）、成员数（群聊）等。
中间区域：消息展示区，按时间顺序展示历史消息，支持滚动加载更早消息，不同消息类型（文本、表情、文件等）需有不同样式。
底部输入区：包含文本输入框、表情选择按钮、文件上传按钮（后续扩展）、发送按钮。
1.3 状态与反馈
WebSocket 连接状态：在界面某个角落（如右下角）显示连接状态（在线/离线/重连中），确保用户知晓实时性。
消息送达状态：消息发送后，本地先显示“发送中”占位，服务器确认后变为“已发送”，失败则显示红色感叹号并支持重发。
未读消息提醒：浏览器标签页标题闪烁或显示未读数量（使用 Web Notifications API 可选）。
二）、系统架构设计
2.1 整体架构分层
沿用现有系统的 MVC 模式，但针对聊天特性增加 WebSocket 长连接层。
层次	组件	职责
前端	聊天主页面（HTML/CSS/JS）	渲染界面、处理用户输入、通过 WebSocket 收发消息、调用 HTTP API 获取历史消息/会话列表
网关	Tornado Web 服务器	处理常规 HTTP 请求（获取会话列表、好友列表、上传文件），同时升级 WebSocket 连接
控制器	新建 ChatHandler（HTTP）和 ChatWebSocketHandler	HTTP：处理会话列表、历史消息、文件上传等 REST 接口；WebSocket：处理实时消息推送、心跳、消息确认
模型层	新增聊天相关数据表
服务层	可选的消息队列（若需要高并发）	消息异步处理、离线消息存储
2.2 模块划分（按功能域）
会话管理模块：负责维护用户的会话列表（私聊+群聊），聚合最后一条消息、未读数。
消息收发模块：负责实时消息的发送、广播、存储、拉取历史消息。
联系人模块：负责好友关系、群组成员关系、用户搜索。
文件传输模块（后续任务实现）：负责文件上传、下载、存储去重。
数字员工模块（后续任务）：负责识别 @数字员工 的消息并触发 AI 回复。
2.3 数据流设计
首次加载：
前端打开聊天页面，通过 HTTP API 拉取用户的会话列表和好友列表。
建立 WebSocket 连接（携带用户身份 token）。
后端根据当前用户 ID，将该 WebSocket 连接注册到用户连接池中。
发送消息：
用户在输入框输入文本，点击发送，前端通过 WebSocket 发送消息对象（包含目标 ID、类型、内容）。
后端接收后：
生成消息 ID、时间戳，存入数据库。
若目标是在线用户，直接从连接池中找到对方连接，推送消息。
若目标离线，则只存储，待对方上线后拉取离线消息。
发送端收到服务器确认后，将消息展示在聊天窗口中。
拉取历史消息：
当用户打开某个会话时，前端通过 HTTP 请求拉取最近 N 条消息，滚动时再加载更早消息。
2.4 关键技术选型（仅设计层面）
WebSocket：使用 Tornado 自带的 WebSocketHandler，结合 @tornado.websocket.WebSocketHandler。
心跳机制：客户端每隔 30 秒发送 ping 帧，服务器回复 pong，断开无响应连接。
消息时序：使用数据库自增 ID 或时间戳排序，保证顺序。
未读计数：在消息表中增加 is_read 字段，当用户打开会话时批量更新为已读。
三）、页面布局与优化设计
3.1 整体布局（沿用现有系统的深色科技感风格）
宽度：聊天主界面占满内容区域（可设置左右边距，但不溢出）。
左右比例：左侧面板宽度 280px（可折叠或拖拽调整），右侧聊天窗口自适应。
响应式：当窗口宽度小于 900px 时，左侧面板自动隐藏，通过汉堡菜单按钮滑出。
3.2 左侧面板优化
会话列表项：
头像：圆形或圆角矩形，可显示好友头像（若无则显示首字母）。
名称：最多两行，超出省略。
最后消息预览：一行，超出用“...”结尾。
时间：显示时/分/秒，昨天的显示“昨天”，更早显示“月/日”。
未读红点：右上角显示数字（超过99显示“99+”）。
通讯录列表：
分组标题（如“我的好友”），分组可折叠。
每个好友项显示在线状态（绿点表示在线）。
支持字母索引条（仅当好友数超过20时）。
搜索框：实时搜索（输入时过滤），支持搜索好友昵称、群聊名称。
3.3 右侧聊天窗口优化
消息气泡：
自己发送的消息靠右，背景色为渐变色（如 #00d4ff 到 #7b2ff7），对方消息靠左，背景色为半透明白色。
消息气泡带有圆角，头像位于气泡外侧。
支持显示消息发送状态（已读回执可选）。
表情支持：点击表情按钮弹出面板，显示常用 emoji 或动态表情（支持自定义表情包）。
文件消息：显示文件图标、文件名、大小，点击可下载。
@提及功能：在群聊输入框中，输入 “@” 弹出成员列表，选择后高亮显示。
3.4 性能与体验优化
虚拟滚动：消息列表只渲染可视区域附近的 DOM，支持大量消息。
图片懒加载：聊天中的图片消息使用缩略图，点击查看原图。
本地缓存：将已加载的会话列表、历史消息存入 IndexedDB，二次打开时先展示缓存再更新，提升感知速度。
断线重连：WebSocket 断开后自动重连（指数退避），重连成功后自动拉取离线消息。
3.5 主题一致性
沿用现有系统的深色背景（#050810 渐变）、发光边框、粒子动效。
聊天窗口内的滚动条使用细窄自定义样式（与全局风格一致）。
按钮 hover 效果：渐变光晕、轻微上浮。
